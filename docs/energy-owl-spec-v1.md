# Energy Owl v1 — Locked Specification

This is the single source of truth on what Energy Owl v1 is and isn't.
Both Claude.ai (in this project) and Claude Code (via CLAUDE.md) should
defer to this document on scope questions.

## One-sentence definition

A polished single-page demo at `energy-owl.shiftatlas.tech` where a user
enters a US commercial building address and receives a 3D roof visualization,
solar production estimates, payback math, and a 1-page AI-generated narrative
report — in under 30 seconds.

## Target user

The user of the demo is a portfolio viewer:
- A prospect evaluating Shift Atlas for AI/automation consulting work
- A LinkedIn connection following JP's portfolio
- A potential future client in commercial real estate, solar, or energy
- Andy Stauffer-type ICP — founder/ops leader, not a solar industry insider

The user is NOT a solar installer designing real systems. They're
evaluating "can this person build sophisticated AI-driven domain
intelligence pipelines."

## The signature pattern this demonstrates

Address in → multi-API pipeline → AI-synthesized scored output

This is the same pattern as Quick Scan and (future) RFP Aggregator.
Energy Owl proves the pattern works in a different vertical with
a strong visual dimension.

## v1 scope — explicit IN list

1. **Single-page Vite + React + TypeScript + Tailwind app.**
2. **Address input field** with submit button. US commercial addresses only.
3. **3D scene** built with @react-three/fiber + drei showing:
   - The building's roof segments derived from Google Solar buildingInsights
   - Proper pitch and azimuth per segment
   - A subtle ground plane and ambient lighting
   - Camera positioned at an isometric-friendly angle, orbit controls
   - Roof segments shaded by their estimated sunshine quality
     (lighter = more sun, darker = less)
4. **Numeric results panel** showing:
   - Estimated annual production (kWh/year) from NREL PVWatts
   - Capacity factor
   - Roof area (m²)
   - Max panel count
   - Today's irradiance (from Open-Meteo)
   - Rough payback estimate (using a default cost-per-watt assumption)
5. **AI narrative report** generated by Anthropic Claude API:
   - 1 page, ~400 words
   - Practitioner voice, no marketing fluff
   - References the actual numbers from the APIs
   - Caveats clearly stated (default assumptions, not a real engineering study)
6. **Branded report styling:**
   - Deep Forest background, Off-white text
   - Sage and Gold accents
   - Instrument Serif headings, DM Sans body
7. **Deployed to Vercel** at `energy-owl.shiftatlas.tech` (or a subdomain
   we configure during S5).
8. **Linked from shiftatlas.tech** alongside Quick Scan in the portfolio /
   tools section.

## v1 scope — explicit OUT list

The following are explicitly OUT of v1. Don't build them. Don't help an
AI build them. Park them as "v2 candidates."

- ❌ Backend / serverless functions (browser-side API calls accepted for v1
  with `// TODO(v2):` markers on exposed-key code paths)
- ❌ Google Solar `dataLayers` GeoTIFF processing — that's a separate
  geospatial workstream
- ❌ Headless rendering / Puppeteer / bulk-processing pipeline
- ❌ Photorealistic panel models — flat shaded rectangles are fine for v1
- ❌ Flux heatmap textures on roof (parked for v2 if dataLayers is added)
- ❌ Multiple-property comparison view
- ❌ Battery storage modeling
- ❌ Permit packages, single-line diagrams, wire sizing
- ❌ Real-time electricity pricing (ERCOT, etc.)
- ❌ International addresses
- ❌ Residential / pitched-roof handling
- ❌ User accounts, saved reports, sharing infrastructure
- ❌ Lead capture / email opt-in / CRM integration
- ❌ A/B testing or analytics beyond a single Plausible/GA snippet
- ❌ Animations beyond R3F's natural rotation and orbit controls

## Done criteria for v1

v1 ships when ALL of these are true:

1. Live at a public URL on a shiftatlas.tech subdomain
2. Address submission triggers all three data API calls successfully
3. The 3D roof is recognizable as the actual building's footprint
4. The numeric results panel populates with real numbers
5. The AI narrative reads as a coherent, useful 1-pager — not generic
6. The page is responsive on mobile (basic — no horizontal scroll,
   readable text, 3D scene scales)
7. Total cost per address-submission is under $0.10 (Claude API only;
   Google Solar and NREL stay within free tiers)
8. README on GitHub explains the architecture and is link-worthy
9. Pinned on JP's GitHub profile
10. Featured on shiftatlas.tech alongside Quick Scan

## Anti-goals (explicit)

- This is NOT a product. There is no "users." There is no "growth."
- This is NOT optimized for solar installers. They have Aurora.
- This is NOT a competitive lead-gen widget. It's a portfolio artifact
  that happens to be useful enough to be interesting.
